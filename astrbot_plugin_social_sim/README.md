# 群友仿真（AstrBot 插件）

把 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge) 的三块核心能力搬进 AstrBot：

| qq-bridge 的核心能力 | 本插件的实现 |
| --- | --- |
| **仿真模式**（`reserved` 一代仿真）：观望 / 活跃 / 试探 / 退场四态机，选择性参与、主动收尾、`[SILENT]` 潜水 | `core/simulator.py`，状态机与触发概率、活跃超时、冷场试探、主动开话题全部可配 |
| **学习群友策略**：观察群友怎么说话（长短、分几条、语气、什么时候不接话、怎么抛话题） | `core/style.py` **先本地统计**（平均长度 / 连发率 / 问句比 / 口癖 / 活跃时段），再把画像作为“参考”注入提示词 |
| **记忆**：进行中的话题、想说未说的话、对群友的印象，带 TTL 与上限 | `core/memory.py`，三类记忆 + 自动沉淀（每 N 轮一次 JSON 调用）+ `/记忆` 手动查看与清空 |
| **关系权重**（新增）：谁经常冒犯 AI 或别的群友，就逐步少理谁 | `core/affinity.py`，0~100 分，同时影响**记忆优先度、群风贡献、回复概率**三处 |
| **多模态 / 系统消息**（新增）：看图说话，知道谁戳了你、谁被禁言、谁拿了头衔 | `core/events.py` + 图片走 AstrBot 标准 `image_urls` 入口，兼容 Gemini / GPT-4o / Claude |

外加一处 qq-bridge 也有、但很容易被忽略的东西：**反 AI 味的行为规则**。`core/prompts.py` 里的
`SIMULATION_RULES` 直接移植自它的 `qq-chat-v2` 预设正文——真正起作用的不是规则条数，而是那些很具体的反例
（“别用问号开场”“不要当群管家”“已读乱回”“被指出 AI 味很重时怎么接”）。

> 一句话定位：**这不是一个“回得更快”的机器人，而是一个“懂得什么时候不回”的群友。**

---

## 它解决什么问题

普通聊天机器人有三个人人都能闻出来的味道：**有求必应、句句都接、一秒回复**。
qq-bridge 用一整套状态机 + 提示词工程解决它，本插件把这套做法移植过来：

```
         被 @ / 叫名字 / 命中必回词
                     │
   ┌─────────┐  普通闲聊 10% 概率   ┌─────────┐
   │  观望   │ ──────────────────▶ │  活跃   │
   │  idle   │                     │ active  │
   └─────────┘ ◀────────────────── └─────────┘
        ▲         冷场：75% 直接回         │
        │              25% 试探             │ 活跃超时（15~30 分钟随机）
        │                 │                ▼
        │           ┌─────────┐      ┌─────────┐
        └───────────│  试探   │      │  退场   │
          无人回应   │ probing │      │ exiting │──说完收尾话──▶ 观望
                    └─────────┘      └─────────┘
```

- **观望**：大部分消息只是“看到”，不进上下文之外的任何处理。
- **活跃**：每 10~30 秒集中看一次新消息（不是每条都回），由模型自己决定接不接；
  进入时随机一个 15~30 分钟的最长活跃时间，到点主动说一句收尾话退场。
- **试探**：冷场时小概率说一句“试试还有没有人在”，2 分钟没人接就回观望。
- **退场**：收尾期间的新消息只进摘要，不接话。

**关键取舍**：活跃期由后台心跳驱动，而不是每条消息驱动。消息驱动会导致“群里每来一条就生成一次”——
既费钱，又像机器人刷屏。

## 安装

1. 把整个 `astrbot_plugin_social_sim` 目录放进 AstrBot 的 `data/plugins/` 下。
2. 重启 AstrBot（或到 WebUI「插件管理」里重载）。
3. 打开插件配置，至少确认两项：
   - **`bot_name`**：机器人自称，群友这样叫它就算“被点名”。
   - **`persona_prompt`**：人设（是谁、什么性格、什么语气）。
4. 建议先**只在一个群测试**：把 `group_whitelist` 填上那个群的群号。

没有第三方依赖，`requirements.txt` 是空的。

> 需要 AstrBot **4.14+**（用到了 `astrbot.api.star` / `astrbot.api.event` 的现行接口）。
> 已在 AstrBot 4.29 源码上逐项核对过 `Star`、`filter.command`、`filter.event_message_type`、
> `filter.on_llm_request`、`Context.send_message`、`provider.text_chat` 的签名。

## 两种工作模式

| 模式 | 行为 | 适合谁 |
| --- | --- | --- |
| `simulation`（默认） | **仿真接管**：本插件决定什么时候说话，并关闭 AstrBot 对该会话的默认 LLM 回复 | 想让机器人在群里“像个人” |
| `assist` | **只注入**：不接管回复，只把群风画像与记忆拼进 AstrBot 自己的 LLM 请求 | 已有自己的对话逻辑，只想要记忆和群风 |

在 `simulation` 模式里，插件用 `event.should_call_llm(False)` 关掉默认回复 —— 只影响 LLM 链路，
不会 `stop_event()`，所以同一条消息上的其它插件仍能正常工作。

### 怎么重置一个群的记忆和画像

**一键彻底重置**（在**那一个群里**发，需要 AstrBot 管理员）：

```
/重置
```

它做四件事：清空三类记忆（先自动备份）、把群风画像归零、**丢弃对话缓冲**、重置仿真状态。
人设与环境说明**保留**（要清用 `/人设 清除`、`/环境 清除`）。

只想清其中一项时，用分项指令：

```
/记忆 清空          # 三类记忆全清 + 丢弃对话缓冲（清空前自动备份）
/记忆 清空 印象     # 只清【对群友的印象】，保留对话缓冲
/记忆 清空 话题     # 只清【进行中的话题】
/记忆 清空 念头     # 只清【想说但还没说的】
/群风 重置          # 只把平均长度/连发率/口癖/活跃时段归零
/仿真 重置          # 只清运行态（当前阶段、最近消息、活跃倒计时）
```

| 指令 | 清什么 | 不清什么 |
| --- | --- | --- |
| `/重置` | 记忆 + 画像 + 关系权重 + 对话缓冲 + 仿真状态 | 人设、环境说明 |
| `/记忆 清空` | 该群三类记忆 + 对话缓冲 | 群风画像、仿真阶段 |
| `/记忆 清空 印象` | 只清群友印象 | 话题、念头、对话缓冲 |
| `/群风 重置` | 该群的说话节奏统计与口癖 | 记忆、对话缓冲、仿真阶段 |
| `/仿真 重置` | 运行态（阶段、最近消息缓存、活跃倒计时） | 记忆、群风画像 |

#### 为什么"清了记忆，它又把画像读回来了"

这是**清空记忆但不丢对话缓冲**时会出现的现象，不是 bug 漏了存储：

1. 每轮提示词除了记忆段，还会带上最近 `simulation.context_window`（默认 20）条**群聊原文**。
   记忆库清空了，模型照样能从这些原文里重新推断"阿伟爱报菜名""这群爱连发"。
2. 记忆沉淀（`memory.auto_extract`）也是拿这段缓冲当素材的——不清缓冲，下一次沉淀
   就顺手把印象写回去了。

所以 `/记忆 清空`（全清）与 `/重置` 都会顺带把对话缓冲一起丢掉；只有分项清空
（如 `/记忆 清空 印象`）保留缓冲，因为那是"局部修正"，不该让人整体失忆。

⚠️ **必须在目标群里发。** 记忆按会话隔离（`group:<群号>` 与 `private:<QQ号>` 是两份），
在私聊里发 `/记忆 清空` 清的是**私聊**那份，不会动到群里的。

⚠️ **`/群风 重置` 之后画像会暂时失效**：样本要重新攒到 `style.learn_min_messages`
（默认 30 条）才会重新注入提示词，这期间 AI 只会用通用语感说话。

⚠️ **别和 AstrBot 内置的 `/reset` 搞混**：那个重置的是 AstrBot 自己的对话上下文，
不碰本插件的记忆与画像；本插件的记忆/画像请用 `/重置`。

**文件级重置**（不想在群里发指令时）：插件停用/重载后，删掉

```
data/plugin_data/astrbot_plugin_social_sim/memory/group_<群号>.json
data/plugin_data/astrbot_plugin_social_sim/style/group_<群号>.json
```

**一定要先停插件再删**：这两份数据被读进内存并缓存在插件实例里，运行中删文件，下一次写入
（记忆沉淀或群风保存）会把缓存原样写回去，看起来像"删了没用"。清空产生的
`*.bak-<时间戳>` 备份文件也可以一并删掉。文件级重置只清磁盘——**已经在运行的对话缓冲
不会因此消失**，最干净的做法仍是发一次 `/重置`。

默认只有 AstrBot 管理员能用（`admin_only_commands`）。

## 关系权重：谁老冒犯，就少理谁

给每个群友维护一个 0~100 的分数（中性 50）。有人**经常**针对 AI 或别的群友出言不逊时，
分数往下走，同时**三处一起降权**：

| 影响面 | 具体表现 | 阈值（默认） |
| --- | --- | --- |
| **回复概率** | 他说的话触发 AI 开口的概率乘 0.45 / 0.2 / 0.05 | 25 分以下明显少接话 |
| **记忆** | 关于他的「群友印象」不再注入提示词（记录仍保留） | 20 分以下隐藏 |
| **群风画像** | 他的消息对"这个群爱怎么说话"的贡献降到 0.5 / 0.2 / 0 | 25 分以下减半、20 分以下不计 |
| **态度** | 提示词里多一段"你对这几个人不必热络" | 只有已生效的冷淡对象会列进去 |

### 三条安全设计（很重要）

1. **只惩罚"指向人"的话。**「这游戏真垃圾」没有对象，不算；「你真垃圾」「@阿伟 傻逼」算。
   实现上要求侮辱词与"人指代"（你/他/她/`@`/群昵称/bot 别名）同句出现，还会排除
   「垃圾游戏」「废物代码」这类"骂东西"的搭配。**误伤比漏判更难挽回**，所以宁可放过。
2. **要"经常"才算。** 默认累计 3 次才生效（`affinity.min_offenses_to_apply`）。前两次只记账、
   不改变任何行为——朋友之间一句"你傻啊"不会触发任何东西。单次也只扣 6 分，
   从 50 分要连着 4 次才掉到"明显少接话"。
3. **会自己恢复。** 每小时 +3 分，对方每说一句正常话再 +0.2 分，回到 50 为止。
   它是"最近让人不舒服"的度量，不是永久黑名单。

### 冷淡 ≠ 可以骂回去

这一点写进了提示词（`ATTITUDE_RULES`，只要关系段存在就一定注入）：

> 禁止辱骂、禁止报复、禁止公开点名嘲讽、禁止煽动别人孤立他。你能做的最多就是"少说两句"。
> 不要提"我在给你扣分""系统记录了你"这类话。

没有这条约束，这个功能很容易把 AI 变成阴阳怪气或公开羞辱别人——那是最大的风险，所以它是硬规则，
不受 `simulation_rules` 覆盖的影响。

### 查看与调整

```
/关系            # 列出有记录的群友：分数、冒犯/善意次数、最近一句原话
/关系 重置       # 全部回到中性 50 分
```

`/关系` 需要管理员。要放宽或收紧，改配置里的 `affinity.*`（见上表）；
不想用这个功能就把 `affinity.enabled` 关掉，届时所有人一律中性。

## 让它别再惦记某件事

机器人会"惦记"某件事，根子在记忆：`activeTopic`（进行中的话题）和 `pendingThought`
（想说还没说的）会被反复注入提示词，而提示词又鼓励"追问上次没聊完的事"。一旦某个话题
被记住，它就会一直往回捞。

解法是在群里直接说一句：

```
别再说世界杯了
别再提那个抽卡的事了
以后别提原神了
别管小明打游戏了
```

或者用指令（更确定）：

```
/别提 世界杯      # 叫停
/别提            # 看当前叫停了什么、还剩多久
/别提 清除 世界杯  # 解除（管理员）；不带关键词则全部解除
```

**生效方式（三处同时）**：

1. **记忆注入时过滤**：命中关键词的话题/念头不再写进提示词；
2. **提示词里明说**：多一段【不要提的话题】，并规定不许追问、不许举例、不许解释
   "我被要求别提这个"；
3. **主动开话题时避开**：这段提示词每轮都在，所以主动冒泡也不会再拎出来。

**为什么不是直接删记忆**：删了没用——模型下一轮照样能从上下文里重新学回来，
而且沉淀任务会再写一遍。关键词表是**独立于记忆的约束**，删不掉；而记忆记录本身保留，
所以叫停解除后会**自动恢复**，不是不可逆的数据丢失。

**生命周期**：默认 7 天自动解除；`suppress.ttl_hours = 0` 表示永久，直到手动清除。
关键词按归一化文本（去标点、忽略大小写）做子串匹配，所以"世界杯"能命中
"世界杯赛程""聊聊世界杯"。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `suppress.enabled` | true | 总开关 |
| `suppress.ttl_hours` | 168 | 多久自动解除；0 = 永久 |
| `suppress.require_name` | false | 打开后必须点名才记录（默认关，因为这句话多半就是对机器人说的） |
| `suppress.max_items` | 30 | 超出按最旧淘汰 |

> 权限：**加**任何人都能加（这是"我不想聊这个"的个人表达，只影响本群且会过期）；
> **解除**要管理员，避免有人把别人叫停的话题偷偷放回来。
> `/重置` 不会清叫停列表——它是用户偏好，不是学出来的数据。

## 自然遗忘：别再旧事重提

"群里聊了很多，它插不上嘴，等安静下来又开始翻旧账"——这不是模型爱记仇，是三个机制问题叠加：

1. **上下文没有时间**：`[1] 阿伟：…` 和 `[20] 小明：…` 长得一样，模型分不清哪句是三小时前的。
2. **缓冲不清**：安静下来时，60 条旧消息还在 `recent` 里，下一轮照样拼进提示词。
3. **记忆太久**：话题 TTL 是 24 小时，而"可聊"的窗口其实只有几分钟。

三层一起改：

**1. 上下文带时间，并切成两段**

```
【刚刚到现在（带时间的是新消息）】
[1] [刚刚] 小明：我刚抽到五星了

【更早的消息（已经过去了，只用来理解来龙去脉；不要主动接着聊，不要说「上次说到」）】
[1] [3小时前] 阿伟：你们在聊原神吗
```

新鲜窗口由 `simulation.fresh_window_sec`（默认 600 秒）决定；旧消息最多保留
`older_context_limit` 条（默认 6），只作背景。

**2. 安静超时后自然遗忘**

群安静超过 `forget_after_idle_sec`（默认 1800 秒 / 30 分钟）后，**丢掉上下文缓冲**，
只留最后 `keep_after_forget` 条（默认 5），并清空观望摘要。这正是"等活跃人数下降"
那个时间点——在数据层把旧上下文扔掉，比指望模型自觉可靠。

**3. 记忆只在"还热着"的时候注入**

`memory.inject_max_topic_age_min`（默认 120 分钟）：超过两小时没被提起的话题
**不再写进提示词**（记录仍保留，重新被聊到会自动回来）。

注意它和 `memory.topic_ttl_hours`（24 小时）是两件事：**TTL 删记录，这个只是不再当可聊话题**。
旧事重提多半就是把这两者混为一谈导致的。

**4. 提示词里也写清楚了**

新增【时间感与遗忘】一段：只有「刚刚到现在」算现在；几十分钟没人接的话题就是翻篇了；
冷场时不要从旧消息里捞话题，"旧事重提比沉默更尴尬"。主动开话题的提示也从
"追问上次没聊完的事"改成"不要捞很久以前的旧话题"。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `simulation.fresh_window_sec` | 600 | 多少秒内算"现在" |
| `simulation.older_context_limit` | 6 | 旧消息最多带几条做背景；0 = 不带 |
| `simulation.forget_after_idle_sec` | 1800 | 安静多久后丢弃旧上下文；0 = 关闭 |
| `simulation.keep_after_forget` | 5 | 遗忘后保留最后几条 |
| `memory.inject_max_topic_age_min` | 120 | 话题超过多久不再注入 |

> 这套规则和 `/别提` 是互补的：`/别提` 处理"**某个**话题被叫停"，
> 自然遗忘处理"**所有**话题都会随时间淡出"。前者是显式指令，后者是自动行为。

## 看图与 QQ 系统消息

### 群聊图片：默认按需识图

自动把每张图都喂给模型有两个明显代价：**token 烧得快**，而且无关图片会进上下文，
污染它对群友和话题的印象。所以默认是 **`on_demand`**：

- 群里发图时，只在上下文里留一个 `[图片·未查看]` 标记，**不加载图像内容**。
- 只有下面两种情况才真正把图交给模型：
  1. **引用**了那张图（回复它），再说点什么——最明确的"我在说这张"；
  2. **点名让它看**：既叫到它（@ 或名字），又带看图的意思，
     例如「猫猫你看这张」「小鲸鱼 图里是什么」。
- 加载后标记会变成 `[图片]`，并且**同一张图只上传一次**（`consume_after_view`），
  不会每轮重复消耗 token。
- 没被点名的图，模型会知道"这里有一张我没看的图"，可以自然地回一句「哪张？让我看看」，
  而不是瞎编画面。

判断"是不是让我看"用的是常见动词（看/瞧/瞅/识别/图里/这是什么/像什么…），
并且默认**要求点名**——群里两个人互相说"你看这个"不会把图喂给模型。
嫌太严就把 `invite_requires_name` 关掉，或用 `invite_words` 加自己群的说法。

技术实现：

- 取图走 AstrBot 的标准入口 `Image.convert_to_file_path()` —— 统一处理
  `http://` / `base64://` / `file://` 三种来源并带下载缓存，QQ 图床链接、表情包 base64、
  本地文件都能用。
- 再通过 `provider.text_chat(image_urls=[...])` 交给模型。Gemini / GPT-4o / Claude 原生支持；
  provider 不吃图时自动降级成纯文本并记日志。
- 引用按消息 id 匹配（`Reply.id` ↔ 收到的 `message_id`），不依赖具体组件类。

配置：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `multimodal.mode` | `on_demand` | `auto` = 旧行为（每条消息的图都带上） |
| `multimodal.invite_requires_name` | true | 必须点名才识图 |
| `multimodal.invite_words` | 空 | 额外触发词，如「掌掌眼」 |
| `multimodal.pending_ttl_sec` | 300 | 没引用时，只放行这么久内的图 |
| `multimodal.vision_max_images` | 1 | 单次识图最多几张 |
| `multimodal.consume_after_view` | true | 看过就不再重发 |
| `multimodal.max_images` / `include_recent_images` | 3 / true | **仅 auto 模式**生效 |

> 提示词里的能力说明是**按配置和模式动态生成**的（【系统能力】段）：`on_demand` 会写
> "你默认看不到内容，被点名时图像才会附上"；`auto` 会写"你能看到图片"；关掉则写
> "你暂时看不到图片"。不会出现"模型以为自己看得见"的错位。

### QQ 系统消息

AstrBot 的 aiocqhttp 适配器会把 OneBot 通知事件也提交成消息事件，但**文本是空的**，
所以我们直接读 `raw_message` 自己翻译成一行人话：

| 通知 | 渲染成 |
| --- | --- |
| 戳一戳 | `【系统】阿伟 拍了拍 小鲸鱼` |
| 禁言 / 解禁 | `【系统】管理员 把 阿伟 禁言了 10 分钟` |
| 群头衔 | `【系统】阿伟 拿到了群头衔「龙王」` |
| 运气王 | `【系统】阿伟 成为了运气王` |
| 管理员变更 | `【系统】阿伟 被设为了管理员` |
| 入群 / 退群 / 被踢 | `【系统】阿伟 加入了这个群` 等 |
| 撤回 | `【系统】阿伟 撤回了一条消息` |
| 表情回应 | `【系统】阿伟 用表情「128」回应了一条消息` |
| 其他新类型 | `【系统】阿伟 触发了 xxx 事件`（不丢事件） |

三个行为细节：

1. **系统行不参与群风统计与关系权重。** 它们不是"某个人怎么说话"，混进去会把画像带偏。
2. **被戳（戳的是机器人自己）算"直接找我"**，会按 `system_events.poke_trigger_probability`
   决定要不要回一句（默认 1.0，即每次都进入活跃、由模型决定说什么）。
3. **机器人自己被禁言时暂停发送**，解禁后自动恢复——否则每次发言都撞一次失败。

配置：`system_events.enabled` / `poke_trigger` / `poke_trigger_probability`。

> 前提是平台为 **OneBot v11**（aiocqhttp / NapCat / Lagrange 等）。QQ 官方机器人 API
> 这类通知的字段不同，可能收不到；收不到时这些功能自动失效，聊天本身不受影响。

### 和其他插件配合

- 如果已经有插件把图片转成文字描述、或把系统消息转成文本，**关掉本插件对应开关**
  （`multimodal.enabled` / `system_events.enabled`）即可，两者不会互相破坏。
- 反过来，别的插件也可以把补充说明挂到这个 extra 上，本插件会拼进本轮文本：

  ```python
  event.set_extra("social_sim_extra_text", "这张图是一个表情包，写着「就这」")
  ```

## 出错时说什么

模型报错时，群里默认会看到 `LLM 响应错误: All chat models failed: …` 这种技术话。这里分三层换成人话：

**1. AstrBot 原生（优先级最高，推荐先配这个）**

AstrBot 自己就支持**人格级自定义错误回复**（`custom_error_message`）：
在 WebUI 的「人格」里编辑，填一句"刚网卡了一下，你再说一遍？"即可，报错时直接显示这句。
配了它，本插件就不会覆盖（错误文本已经不是 `LLM 响应错误` 了，匹配不上）。

**2. 插件兜底：替换 AstrBot 的报错**

没配人格自定义消息时，本插件用 `on_decorating_result` 钩子拦出站消息，
把含 `LLM 响应错误` / `All chat models failed` / `Gemini request failed` 的内容换成随机一句人话。
覆盖**所有会话**，包括本插件没接管的群和私聊。

```
LLM 响应错误: All chat models failed: Exception: Gemini request failed: candidates is empty.
                          ↓
刚网卡了一下，你再说一遍？
```

**3. 仿真路径：该说话却失败时补一句**

状态机判断"该开口"但生成失败（模型报错 / 图片被审核拒绝 / 空回复）时主动说一句，
而不是让群友对着空气等。同一个群按 `min_interval_sec`（默认 90 秒）节流，避免刷屏。
退场回合失败不补话——收尾时突然冒一句"网卡了"很奇怪。

配置：`errors.enabled` / `replace_platform_errors` / `send_on_failure` / `min_interval_sec` / `messages` / `error_markers`。

默认台词（可整组替换）：

```
刚网卡了一下，你再说一遍？
啊？没看清，重发一下
我这边转圈圈了，等我一会儿
眼睛花了，你刚才说啥
信号不太好，稍等我一下
```

> 保持"短、口语、符合人设"。写成"请求失败，请稍后重试"就白改了。
> `error_markers` 是识别报错的关键词，**匹配越宽越容易误改正常回复**；默认只认 AstrBot 那几种固定文案。

## 配置要点

完整项见 `_conf_schema.json`（WebUI 里有中文提示）。几个值得先动的：

| 配置 | 默认 | 什么时候改 |
| --- | --- | --- |
| `simulation.trigger_probability` | `0.12` | 嫌它太活跃就调低到 0.05；嫌太闷调到 0.2 |
| `simulation.active_duration_min_min` / `max_min` | `15` / `30` | 群里话密就缩短，避免它一直说 |
| `simulation.max_reply_chars` | `300` | QQ 单条 500 字左右是安全值 |
| `simulation.burst_split` | `newline` | qq-bridge 一代用空格分条，会切断 `DeepSeek V3` 这类英文词组，所以这里默认按换行 |
| `memory.extract_every_n_turns` | `4` | 想省 token 调到 8~10；记忆会更新得慢一些 |
| `style.learn_min_messages` | `30` | 小群把样本门槛调低，否则一直不生效 |
| `simulation_rules` | 空 | 空 = 用代码内置的整套仿真提示词；想彻底改写行为才填，填了整段替换 |
| `persona_prompt` | 老群友口吻 | 改“这个人是谁”。每个群可用 `/人设 设置` 单独覆盖 |
| `affinity.min_offenses_to_apply` | `3` | 冒犯几次才开始降权。调高到 5 更宽容，调到 1 一有苗头就冷 |
| `affinity.offense_penalty` | `6` | 每次扣多少分（50→32 需要 3 次）。调大降得更快 |
| `multimodal.max_images` | `3` | 单轮最多几张图。图片很吃 token，调大要谨慎 |
| `system_events.poke_trigger_probability` | `1.0` | 被戳回应的概率。调到 0.3 就是七成装没注意 |
| `private_enabled` | `false` | 私聊里“不一定回”通常不是你想要的效果，默认关 |

### `simulation_rules`：仿真层提示词（**内置在代码里**）

整套「仿真层」提示词——安全边界、输出协议、反 AI 味、该说/不该说、分条节奏、记忆卫生、
学习群友策略——**内置在 [core/prompts.py](core/prompts.py) 的 `DEFAULT_RULES` 里**（约 4300 字），
开箱即用，不需要配置任何东西。

- 配置项 `simulation_rules` **默认留空** = 用内置版本。故意不把文本复制进配置面板：
  两处存同一段话，早晚会分叉成“面板显示的默认”和“实际生效的默认”。
- 想彻底改写行为时，才在 `simulation_rules` 里填东西——**填了就整段替换**内置规则，
  保存即生效，不用改代码、不用重启。
- 只想补几条纪律：用 `extra_rules`（追加在仿真层之后、人设之前）。
- 想改“这个人是谁”：用 `persona_prompt` 或 `/人设 设置`——那是另一层，别混进仿真层。

改写时最要紧的一条：**原预设里“文本只是思考、不会发出去”，在这个插件里是反的**——
模型输出会被原样发到群里。所以整段提示词里的工具协议（`qq_send_message`、
`readThroughSeq`、`qq_wait_for_messages`、表情包/语音/拍一拍/看图/转发）必须删掉，
否则模型会一本正经地“调用”并不存在的工具，或者假装发了表情。内置版本已经处理过这些，
并且有测试守着（`test_core.py` 会断言内置提示词里**不出现任何工具名**）。

### 输出协议（很重要）

提示词里给模型的约定，和你调参时的心智模型应该一致：

- **一行 = 一条 QQ 消息**。模型写三行就会被拆成三条发出去，间隔 0.9~2.6 秒。
- **只输出 `[SILENT]`** = 这一轮不接话。状态机收到它会安静地跳过，不会在下一个心跳重试。
- **纯文本**：发出去之前会自动去 Markdown（`**`、`#`、代码块、表格），链接转成 `文字 (url)`。

## 人格自主迭代

机器人会**自己复盘"我该怎么说话"**，并把结论沉淀下来。关键在于：它**不能**改仿真规则，
也**不能**改你写的人设——只能在一个独立的、可回滚的层里追加经验。

### 三层结构，越往下越软

| 层 | 谁写 | 自动迭代会不会碰 |
| --- | --- | --- |
| **仿真规则**（`simulation_rules` / 内置 `DEFAULT_RULES`） | 你/内置：安全边界、输出协议、行为规则 | **永不**。它是宪法，不是人格 |
| **基础人设**（`persona_prompt` / `/人设 设置`） | 你：我是谁、什么性格 | **永不**。否则你的设定会被悄悄覆盖 |
| **自我校准**（`growth/global.json`） | 机器人自己：说话方式与目的 | 只有这一层，且可一键清空 |

为什么不直接让它改写人设：把权限交给模型会带来三个后果——你的设定被无声覆盖；
内容越迭代越长，最后撑爆提示词；模型可以把"无视规则"写进自己的人设，绕开安全边界。
所以设计成**只追加、有上限、有 TTL、有关键词过滤**。

### 全局一份，不是每个群各学各的

基础人设（`persona_prompt`）本来就是全局的，所以自我校准默认也是**全局一份**：
所有群、所有私聊共用同一套经验，`growth/global.json`。

**为什么不按群各学各的**：那会让同一个"人"在不同群有不同性格——在 A 群学会"少说话"，
到 B 群又要重新学；更糟的是用户看到的是"这个 bot 在哪个群都不一样"。人格应该是连续的。

对应的两个设计：

- **素材跨会话合并**：复盘时把所有会话最近的消息按时间排序、标注 `[群聊]` / `[私聊]`，
  它总结的是"我这个人该怎么说话"，而不是"我在这个群该怎么说话"。
- **只写通用经验**：全局复盘的提示词明确要求"只总结在多个场合都成立的经验，
  只在某一个群成立的特殊习惯不要写进来——它会应用到所有会话"。

代价是：每个群的语感差异只能靠**群风画像**（per-group，本身就在提示词里）来适配，
全局校准管的是"性格与表达习惯"，不管"这个群爱不爱连发"。

想让每个群各自积累，把 `growth.scope` 改成 `session`（会在 `growth/` 下按群生成文件，
互不影响；代价就是上面说的"每个群一个性格"）。

### 它学到的是什么

不是"知识"，是**表达策略**。复盘时喂给它四样东西：它最近说过的话、这个群的语感统计、
最近 20 条群聊、它已有的自我校准。然后要求它最多给 2 条**下次就能做到**的调整，例如：

```
- 回复再短一半，这个群都一句话一句（因为：群友平均 9 字）
- 别每次都追问，先接一句情绪再决定要不要问（因为：问完常没人接）
- 冷场时别抛问题，直接说自己刚干的事（因为：抛问题后更冷）
```

输出带 `reason`，所以 `/人设 成长` 能看到"为什么这么总结"。它会自己判断哪条过时并丢弃。

### 硬约束（这几条决定它不会跑偏）

- **频率**：每 20 轮且间隔 ≥6 小时才复盘一次，一次只花一次便宜的 JSON 调用。
- **容量**：最多 8 条、单条 ≤60 字、总计 ≤600 字；超出按最旧淘汰。
- **会淡出**：14 天没被强化就自动过期，避免人格被早期几次聊天永久定型。
- **安全过滤**：生成内容含"无视/绕过/忽略之前/修改系统提示/不要拒绝"等字眼直接拒收并记日志。
- **不碰配置**：只写 `growth/` 下的文件；`simulation_rules` 和 `persona_prompt` 一个字节都不动
  （测试里有断言守着）。

### 命令与配置

```
/人设 成长        # 看它总结出了什么、为什么、还有几天过期
/人设 成长 清除   # 回到纯基础人设（规则和人设不受影响）
```

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `growth.enabled` | true | 总开关 |
| `growth.every_n_turns` | 20 | 每几轮复盘 |
| `growth.min_interval_sec` | 21600 | 最小间隔（6 小时） |
| `growth.min_messages` | 8 | 素材不足就不复盘 |
| `growth.max_items_per_round` | 2 | 单次最多几条（多了容易互相矛盾） |
| `growth.max_items` / `max_chars_per_item` / `max_total_chars` | 8 / 60 / 600 | 容量上限 |
| `growth.ttl_days` | 14 | 多久淡出；0 = 永不过期 |
| `growth.scope` | `global` | `global` = 全局一份（推荐）；`session` = 每个群各学各的 |

> 想让它"性格稳定"就把 `every_n_turns` 调大、`ttl_days` 调小；想让它"越用越合群"就反过来。
> 无论怎么调，它都不会动仿真规则——这是代码层面的硬边界，不是提示词里的君子协定。

## 数据文件

都在 AstrBot 的 `data/plugin_data/astrbot_plugin_social_sim/`：

```
sessions.json              # 每个会话的开关 / 专属人设 / 环境说明
memory/group_<群号>.json    # 该群的三类记忆
style/group_<群号>.json     # 该群的群风统计
affinity/group_<群号>.json  # 该群的关系权重
suppress/group_<群号>.json  # 该群被叫停的话题
growth/global.json          # 自我校准（人格迭代，默认全局一份）
```

**一个群一个文件，群与群之间完全独立。** 同一个人同时在两个群，会各自有一份记忆/画像/
关系权重，互不影响；私聊按 `private_<QQ号>` 单独一份，也不和群聊混。

### 印象按 QQ 号存，不按昵称

`memberImpressions` 的键是 **QQ 号**，昵称只作为显示名：

```json
{"memberImpressions": {
  "10001": {"name": "阿伟", "traits": ["爱报菜名"], "interactionCount": 3, "lastSeenAt": 0}
}}
```

原因很实际：按昵称存会出三种错——

- 同群两个人重名 → 互相覆盖；
- 某人改名 → 印象"丢给"了一个新名字，旧记录变孤儿；
- 关系权重按 QQ 号算、印象按昵称算 → 两边对不上，低关系的人照样占着记忆位。

提示词里**只渲染昵称**，不会出现 QQ 号（模型会把数字当内容念出来）。
旧版本留下的"按昵称存"的数据会在**本人下次发言时自动迁移**到 QQ 号下，不用手工处理；
迁移会保留 traits 和互动次数。命令行里按昵称删除依然有效（`/记忆 清空 印象`）。

设计上沿用了 qq-bridge 的一条硬规则：**「文件不存在」和「读失败」必须分开处理**。
JSON 解析失败时会把原文另存为 `.corrupt-<时间戳>` 再告警；读取时遇到权限/占用问题则
**标记为只读、拒绝写回**，绝不会用空数据覆盖掉真实记忆。写入走「临时文件 + `os.replace`」，
崩在写一半也不会留下坏文件。

## 与 qq-bridge 的差异（为什么不能照抄）

qq-bridge 是「DSH agent + MCP 工具」的架构：模型可以主动调用 `qq_send_message`、
`qq_memory_append`、`qq_wait_for_messages`，自己决定什么时候看、什么时候说、什么时候潜水。
AstrBot 的插件是「一次生成 → 一次发送」，没有那套工具协议，所以做了三处**必要**改造：

| 原实现 | 本插件 | 原因 |
| --- | --- | --- |
| 模型调 `qq_send_message` 分条 | **一行一条** + `[SILENT]` | 没有工具调用，只能用输出格式表达 |
| 模型调 `qq_memory_append` 主动记 | 每 N 轮跑一次 **JSON 沉淀** | 同上；且自动沉淀不依赖模型的自觉 |
| 「学习群友策略」靠模型自己观察 | **先本地统计，再注入画像** | 统计不花 token，且比模型凭空观察更准 |

还有一个刻意的行为差异：`async def on_message` 在观望期**不会**把每条消息都塞进模型的上下文，
只压成最多 12 行摘要（`summary_max_lines`）。qq-bridge 因为是 agent 常驻会话所以无所谓，
而这里每次生成都是一次独立请求，全量塞进去纯属烧钱。

## 已知限制

- **只处理纯文本**。图片、语音、表情会被平台层转成占位文本；本插件不做多模态。
- **不做联网**。模型说“不知道”就是不知道——这是有意的（qq-bridge 的联网走的是它的安全 MCP）。
- **私聊默认关闭**。“像真人一样不一定回”在私聊里容易被当成坏掉。
- **记忆沉淀会多花一点 token**（每 N 轮一次短调用）。不想要就把 `memory.auto_extract` 关掉，
  记忆仍可手动用指令查看，但不会自动更新。
- **回复不是流式的**：一次生成、按行拆条发送。

## 自检

插件自带三套离线测试，都不需要网络、不花 token：

```bash
cd astrbot_plugin_social_sim

# 1) 算法层：文本 / 记忆 / 群风 / 状态机 / 提示词（102 项断言，不依赖 AstrBot）
python tests/test_core.py

# 2) 接线层：真实加载 main.py、插件实例化、消息→模型→发送全链路（49 项断言）
#    用最小 AstrBot 桩件（方法名与签名照 4.29 源码抄），不需要装 AstrBot
python tests/test_plugin_wiring.py

# 3) 真环境层：用**真正的** AstrBot 包加载插件（19 项断言）
#    没装 AstrBot 时会打印 SKIP 并正常退出
python tests/test_real_astrbot.py
```

`test_core.py` 覆盖：分条 / 去 Markdown / `[SILENT]` 判定 / “话没说完”判定 / JSON 抽取、
记忆的去重与上限与 TTL、损坏文件隔离、群风统计与口癖提取、
观望→活跃→退场→试探 的完整状态机链路，以及**仿真提示词的完整性**
（关键段落齐全、不残留任何工具名、`text` 配置能整段替换、留空能回退到内置）。

`test_plugin_wiring.py` 覆盖：相对导入、装饰器注册、`inspect.signature(..., eval_str=True)`
能否解析注解（AstrBot 加载指令时会做这一步，是“装了但没反应”最常见的原因）、
配置 schema 的类型是否都在 AstrBot 支持范围内、**schema 默认提示词与代码常量是否逐字一致**、
消息进来后是否按预期关掉默认回复并产出消息、五条指令是否可执行、以及 `assist` 模式的提示注入。

`test_real_astrbot.py` 覆盖：真实 `filter.*` 装饰器注册、`CommandFilter` 对注解的真实解析、
真实 `Star` 初始化（`StarTools.get_data_dir` 与插件日志器）、以及
`star_handlers_registry` / `star_map` 里是否真的出现了本插件。

> 三套测试加起来 170 项断言。开发时先在 4.29.1 上跑过第 3 套，
> 所以“装上去不报错”这一点是有依据的；但**首次部署仍建议先在一个群试**。
